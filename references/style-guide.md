# 宁的AI小站 - 写作风格指南

本文件从 GoodTime 已发布的 20+ 篇推文中逆向提炼，是排版改写和代写时的语气/结构依据。

## 一、标题风格

### 1.1 系列科普文章标题公式

```
[问题式主标题]——[概念名]全解析
```

实际案例：
- `AI 怎么才能不瞎编？——RAG 检索增强生成全解析`
- `不只是"聊天机器人"——AI Agent 到底是什么？`
- `AI 聊着聊着就"变笨"了？——上下文窗口深度解析`
- `AI 的「记忆」是怎么工作的？——Memory 机制全解析`
- `同一个问题，为什么 AI 每次回答都不一样？——Prompt 工程入门`
- `AI 的"万能插座"——MCP 协议全解析`
- `AI 怎么才能变成"你的人"？——模型微调（Fine-tuning）全解析`
- `AI 在"想什么"？——思维链与推理模型全解析`
- `AI 为什么会"变坏"？——AI 安全与对齐全解析`

### 1.2 实战/复盘文章标题公式

```
[动词]+[宾语]+[· 或 ——]+[补充说明]
```

实际案例：
- `用秒哒从0到1做出一个App · 完整复盘`
- `Windows 原生部署 Hermes Agent + 火山引擎 Agent Plan + Harness + 飞书机器人 完整实战教程与踩坑总结`
- `腾讯 QClaw 实测体验：微信一发指令，本地 AI "小龙虾"帮你高效干活`

### 1.3 标题规律总结

- **用问句**：标题包含问号，激发好奇心
- **口语化**：用"瞎编""变笨""变坏"等接地气的词，不用"幻觉""性能下降""风险"等学术词
- **中英混排**：中文为主，技术名词保留英文原词（RAG、Agent、MCP、Prompt）
- **破折号连接**：主标题用 `——` 连接副标题/概念名
- **不用 emoji**：标题中不使用 emoji

## 二、开头结构

### 2.1 系列文章开头（必须）

```markdown
> 本文是「AI 基础设施科普」系列第 N 篇。上一篇我们聊了 [上期主题]——[一句话回顾]。今天聊 [本期主题]——[一句话钩子]。
```

### 2.2 非系列文章开头

直接用一句话点出核心论断或背景：

```markdown
最近 [事件/工具] 很火，但很多人 [困惑/误解]。这篇文章把 [话题] 从 0 到 1 讲清楚。
```

### 2.3 核心观点前置

开头紧接着给出**一句话核心论断**，加粗：

```markdown
**Chatbot 只能"说话"，Agent 能"做事"。**
```

## 三、章节结构

### 3.1 章节编号

使用中文数字：`一、` `二、` `三、` `四、` `五、` `六、` `七、` `八、`

末章如果是总结，标题为：`八、一句话总结`

### 3.2 问题式章节标题

每个章节标题都是一个**问题**，不是陈述：

实际案例：
- `一、Chatbot 和 Agent 有什么区别？`
- `二、Agent 的核心：感知-思考-行动循环`
- `三、工具——Agent 的"手和脚"`
- `四、Agent 的四层能力演进`
- `五、为什么 Agent 现在才火？`
- `六、普通人怎么用 Agent？`
- `七、Agent 的局限和风险`
- `八、一句话总结`

### 3.3 层级递进逻辑

```
概念是什么 → 核心原理 → 关键组件 → 演进层级 → 为什么现在 → 怎么用 → 局限性 → 总结
```

### 3.4 长文特殊编号系统

实战复盘类长文使用英文标签 + 编号：

| 标签 | 用途 | 格式 |
|------|------|------|
| `PART` | 主章节 | `01 PART` / `02 PART` / `03 PART` |
| `STEP` | 步骤 | `STEP 1` / `STEP 2` / `STEP 3` / `STEP 4` |
| `CASE` | 案例 | `CASE 01` / `CASE 02` / `CASE 03` |
| `FLOW` | 流程图 | `FLOW` |
| `END` | 结尾 | `∞ END` |

## 四、生活类比（核心特色）

### 4.1 类比使用规则

**每个技术概念必须配一个生活类比**，放在引用块中。

### 4.2 类比库

| 技术概念 | 生活类比 |
|----------|----------|
| Chatbot vs Agent | 念菜单的服务员 vs 餐厅经理 |
| 上下文窗口 | AI 的"工作台"大小 |
| Memory 机制 | 昨天聊了半天今天又变成陌生人 |
| RAG | 开卷考试 vs 闭卷考试 |
| Prompt 工程 | 你怎么跟 AI 说话决定它怎么回答 |
| MCP 协议 | 万能插座/USB-C 统一接口 |
| 模型微调 | 让通才变成"你的人" |
| 思维链 | 从"直觉回答"到"一步步推理" |
| AI 安全对齐 | AI 为什么会"变坏" |
| 工具调用 | AI 的"手和脚" |
| Token | AI 的"阅读量"配额 |
| 幻觉 | 自信地瞎编 |
| Agent 循环 | 感知-思考-行动的循环 |

### 4.3 类比格式

```markdown
举个生活类比：

> 你去餐厅，Chatbot 像一个只会念菜单的服务员——你问什么它答什么，但不会帮你下单、上菜、结账。
>
> Agent 像一个真正的餐厅经理——你告诉他"我要办一场十人聚餐"，他自己安排菜单、下单、排座位、催菜，最后把结果交给你。
```

## 五、排版元素使用规则

### 5.1 引用块（>）

三种用途：
1. **系列导语**（文章开头）
2. **生活类比**（概念解释处）
3. **章节小结金句**（章节末尾）

### 5.2 加粗（**）

加粗的内容类型：
- **核心论断**：一句话总结性的判断
- **关键数据**：对比数据中的数字
- **重要结论**：推理后的结论句
- **步骤名称**：如「第一步：感知（Perceive）」

不加粗：
- 普通强调词
- 整段文字

### 5.3 表格

用于对比，居中对齐。标准格式：

```markdown
| 维度 | A | B |
|:-:|:-:|:-:|
| 交互方式 | 你说一句，它回一句 | 你给目标，它拆步骤执行 |
```

### 5.4 代码块

Prompt 类代码块上方加标签：
```
...Prompt

[代码内容]
```

普通代码块不加标签。

### 5.5 图片说明

图片下方加说明，格式：
```
图：[说明内容] —— [补充描述]
```

### 5.6 英文装饰标签

长文中用英文标签做视觉分隔：

| 标签 | 位置 | 含义 |
|------|------|------|
| `EDITOR'S NOTE` | 开头背景说明 | 编辑按语 |
| `FIELD REPORT` | 标题区 | 实地报告/复盘 |
| `EVENT INFO` | 活动信息块 | 活动详情 |
| `FLOW` | 流程图上方 | 流程标记 |
| `END` | 结尾 | 全文结束 |

## 六、语气特征

### 6.1 人称

- **第二人称"你"**：直接对话感
  - "你可能用过 ChatGPT 聊天"
  - "你可能会想"
  - "你给目标，它拆步骤执行"

### 6.2 口语化表达

| 学术/正式说法 | GoodTime 用法 |
|---------------|---------------|
| 模型幻觉 | 瞎编 / 自信地犯错 |
| 性能下降 | 变笨 |
| 产生风险 | 变坏 |
| 模型部署 | 跑起来 |
| 接口调用 | 调工具 |
| 上下文溢出 | 脑子装满了 |
| 参数优化 | 调一调 |
| 功能迭代 | 改了一版又一版 |

### 6.3 数据具体化

不用"大幅提升""显著降低"等模糊词，用具体数字：

```
传统软件开发成本大约2万元、耗时4个月；用秒哒开发成本不到50元、耗时不到1小时。
```

### 6.4 诚实面对局限

每篇科普文必须有「局限和风险」章节，不回避缺点：

```
Agent 很强，但不是万能的。几个值得了解的局限：

1. 幻觉仍然存在
2. 循环可能失控
3. 权限边界难把握
4. 成本可能很高
5. 可解释性差
```

## 七、结尾结构

### 7.1 一句话总结（必须）

最后一段章节标题为「X、一句话总结」，内容用引用块：

```markdown
## 八、一句话总结

> **Chatbot 是 AI 的"嘴"，Agent 是 AI 的"嘴 + 手 + 脑"。** 它不只是能聊天，而是能自己感知环境、规划步骤、调用工具、循环执行，直到把任务做完。
```

### 7.2 下一篇预告（系列文章必须）

```markdown
下一篇我们聊 [主题]——[一句话钩子]。
```

实际案例：
- "下一篇我们聊 Agent 背后的关键技术之一：RAG（检索增强生成）——让 AI 读你的私有数据而不是瞎编。"

### 7.3 作者签名（必须，固定文案）

```markdown
我是 GoodTime，｜全栈·AI讲师·社区主理人｜公众号【宁的AI小站】——用技术让AI更实用。点击主页加群或者私信加群一起学习AI。如果你觉得今天这篇有收获，欢迎点赞、在看、转发三连，我们下篇见。
```

### 7.4 三连引导（必须）

```markdown
如果你觉得今天这篇有收获，欢迎点赞、在看、转发三连，我们下篇见
```

## 八、文章类型速查

### 科普解析系列（11篇）
- 固定导语格式
- 问题式章节
- 生活类比
- 对比表格
- Level 进阶
- 局限性章节
- 一句话总结
- 下一篇预告

### 实战复盘
- FIELD REPORT 标签
- EDITOR'S NOTE 背景说明
- PART/STEP/CASE 编号系统
- 代码块/Prompt 展示
- 图片+说明
- EVENT INFO（如有活动）
- END 结尾

### 工具测评
- 开门见山说结论
- 功能逐项拆解
- 对比表格
- 实测体验标注
- 选型建议
- 局限说明

### 教程指南
- 踩坑提示
- STEP 步骤块
- 代码块
- 截图说明
- 最终效果展示
